## Decisions

- Deploy workflows read the production install name from `vars.WPE_PROD_ENV` instead of hard-coding it, and fail fast if it is unset.
- The one-off Contentful migration scripts (`migrate-takeaways-*`, July 2026, already run) are archived in the private hub, not in `assemble-content`: they delete content and must not be rerun.

- PHP mismatch: beta 8.4, production 8.2. Code must run on 8.2 until production is upgraded (Mark's call). Local wp-env uses 8.2 so incompatibilities show up locally.

## Follow-ups

Installing from the wordpress.org zip would work, but then WP Engine wouldn't offer updates for it, on the beta or on production. Decision #2 needs Mark: (a) SCF from the zip with manual updates (or switch the install's update source to WordPress.org, if WP Engine allows it), or (b) ACF Pro, WP Engine's own product. The theme and `assemble-core` work with either (same `get_field()` / `acf_add_options_page()` API). Until then the beta runs ACF free 6.8, which has no options pages, so Site Settings there use the code defaults.
